# LAITYS WB Study

Небольшой кабинет продавца Wildberries на **FastAPI**: каталог товаров, сводка продаж и учёт дополнительных расходов. Предназначен для изучения разработки, тестирования и эксплуатации веб-сервиса.

Это отдельная учебная адаптация собственного проекта LAITYS. Здесь один маркетплейс, три экрана и полностью вымышленные данные за **1–14 октября 2026 года**. Доступ к Wildberries, API-ключи и файлы рабочего LAITYS не нужны. Интерфейс, API, тесты и расчёты работают локально.

## Что умеет приложение

- Показывает выручку, количество продаж, прибыль и маржу за выбранный период.
- Фильтрует товары по названию и артикулу; показывает карточку товара.
- Сохраняет дополнительные расходы между перезапусками и учитывает их в сводке.
- Выгружает дневную сводку в CSV; предоставляет интерактивную документацию API.

Содержательные доработки относительно исходного LAITYS: сервер FastAPI вместо `http.server`, один маркетплейс вместо нескольких, автономные демонстрационные данные, новый сокращённый интерфейс, настройки окружения, отдельные проверки состояния и версии, тесты pytest и GitHub Actions с artifact.

## Установка

Нужны **Python 3.11 или новее** и Git. Команды выполняются из корня этого проекта. При первом скачивании зависимостей нужен интернет.

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

Если PowerShell запрещает активацию, используйте `.\.venv\Scripts\python.exe` вместо `python` во всех последующих командах. Менять системную политику выполнения не требуется.

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Для обычного запуска без тестов достаточно `python -m pip install -r requirements.txt`.

## Запуск

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Это команда обычного запуска **без `--reload`**. Откройте:

- Кабинет: <http://127.0.0.1:8000/>
- Swagger UI: <http://127.0.0.1:8000/docs>
- Проверка работоспособности: <http://127.0.0.1:8000/health>
- Версия: <http://127.0.0.1:8000/version>

В Windows можно дважды нажать **`Запустить.cmd`**: он создаёт локальное окружение и устанавливает зависимости при первом запуске, затем запускает сервер. Остановить сервер — **Ctrl+C**.

В кабинете доступны «Сводка», «Товары» и «Расходы». Выбранный период влияет на сводку и CSV; каталог показывает показатели за весь демонстрационный период. Прибыль товаров показана до общих дополнительных расходов.

## Настройки окружения

Настройки необязательны: приложение запускается без `.env`. При необходимости скопируйте безопасный пример:

```powershell
Copy-Item .env.example .env
```

В Linux / macOS: `cp .env.example .env`. `.env` загружается автоматически; уже заданные переменные окружения имеют приоритет. После изменения настроек перезапустите сервер.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `LAITYS_SHOP_NAME` | Название магазина в интерфейсе и `/health` | `LAITYS · учебный магазин` |
| `LAITYS_LOG_LEVEL` | Уровень логов | `INFO` |
| `LAITYS_DATA_DIR` | Папка сохраняемых расходов; относительный путь считается от проекта | `.runtime` |

Демонстрационные товары и продажи лежат в `data/demo.json`. Изменяемые расходы сохраняются отдельно, в `.runtime/expenses.json` по умолчанию. Рабочие данные, `.env`, окружение Python и кэши исключены через `.gitignore`.

## API

| Метод и маршрут | Назначение / параметр |
|---|---|
| `GET /health` | Доступность сервиса и хранилища, режим, название магазина |
| `GET /version` | Название и версия приложения |
| `GET /api/products?q=розетка` | Каталог и поиск по артикулу или названию |
| `GET /api/products/{sku}` | Один товар; неизвестный артикул возвращает `404` |
| `GET /api/report?date_from=2026-10-01&date_to=2026-10-14` | Сводка и дневные значения за период |
| `GET /api/expenses` | Список дополнительных расходов |
| `POST /api/expenses` | Добавление расхода; возвращает `201` |
| `DELETE /api/expenses/{id}` | Удаление расхода; возвращает `204` |
| `GET /api/export` | CSV по дням; поддерживает те же даты, что и сводка |

Пример тела запроса добавления расхода в `/docs`:

```json
{
  "date": "2026-10-10",
  "category": "Упаковка",
  "amount": 350.50,
  "comment": "Демонстрационный расход"
}
```

Категории: `Реклама`, `Упаковка`, `Доставка`, `Прочее`. Сумма положительная, до 1 000 000 ₽, максимум два знака после запятой. Комментарий — до 200 символов. Некорректный формат даёт `422`, обратный диапазон дат — `400`. За период вне демонстрационных данных показатели равны нулю; расходы соответствующего периода учитываются даже при отсутствии продаж.

## Как считаются показатели

Денежные расчёты выполняются с точностью до копейки. Учебная комиссия — **20% выручки**, логистика — **35 ₽ за проданную единицу**; это условные значения примера, а не действующие тарифы Wildberries.

```text
Прибыль = выручка − комиссия − логистика − себестоимость − дополнительные расходы
Маржа = прибыль / выручка × 100%; при нулевой выручке — 0%
```

Суммы дней совпадают с итогами сводки. Дополнительные расходы вычитаются один раз на свою дату. Каталог показывает результат товаров до общих расходов. Налоги и реальные финансовые отчёты маркетплейса в учебную модель не входят.

## Тесты

```bash
python -m pytest -v
```

Проверяются `/health`, версия, полезные маршруты, поиск, неизвестный артикул, даты, сверка дневных и итоговых сумм, изменение прибыли после добавления расхода, удаление и сохранение расходов, валидация ввода и настройки окружения. Каждый тест использует отдельное временное хранилище; настоящий кабинет и интернет не используются.

## Логи и диагностика

Логи видны **в терминале, где запущен uvicorn**. Приложение пишет запуск и остановку, HTTP-метод, путь, код ответа и время запроса, а также успешное добавление/удаление расхода. Тела запросов, комментарии и query-параметры в лог приложения не выводятся.

Быстрая проверка из другого терминала:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
```

В Windows при конфликте с псевдонимом PowerShell используйте `curl.exe`.

| Проблема | Что проверить |
|---|---|
| `No module named fastapi` / `uvicorn` | Выбран ли Python из `.venv`; установите `requirements-dev.txt` |
| Порт занят | Остановите предыдущий сервер или запустите с `--port 8001` |
| Пустая сводка | Продажи примера есть только за 1–14 октября 2026; проверьте период |
| Ошибка хранения / `503` в `/health` | Права записи в `LAITYS_DATA_DIR`, доступность и формат `expenses.json`; смотрите терминал |
| Пропало оформление | Открывайте `/` через uvicorn, не `index.html` с диска; проверьте `/static/styles.css` |

Для сброса **только учебных расходов** остановите сервер и удалите `expenses.json` из настроенной папки данных. При следующем запуске восстановятся расходы из демонстрационного примера. При обычном перезапуске изменения сохраняются.

## GitHub Actions и сдача

В `.github/workflows/ci.yml` настроены тесты при `push` и `pull_request` на Python 3.11 и 3.12. После успешных тестов каждая задача сохраняет artifact с приложением, статикой, демонстрационными данными, зависимостями и README.

Для сдачи создайте **пустой публичный репозиторий** GitHub, не добавляя README через веб-интерфейс. Выполните из этой папки, подставив адрес своего репозитория:

```bash
git remote add origin https://github.com/YOUR_USERNAME/laitys-wb-study.git
git push -u origin main
```

Авторизуйтесь в GitHub, если Git запросит вход. Откройте вкладку **Actions**, дождитесь зелёного запуска и проверьте раздел **Artifacts**. Локальный успешный pytest не означает, что удалённый CI уже запускался.

Преподавателю отправьте:

1. Ссылку на публичный репозиторий.
2. Ссылку на последний успешный запуск Actions (страница вида `/actions/runs/...`).
3. Одно предложение: «LAITYS WB Study — учебный сервис FastAPI для анализа демонстрационных продаж Wildberries, поиска товаров и учёта расходов».

В репозитории сохраняется история отдельных этапов этой адаптации. Её можно посмотреть командой `git log --oneline`. При переносе сохраняйте скрытую папку `.git`: загрузка всех файлов одним новым коммитом потеряет эту историю.

Перед сдачей проверьте установку и запуск после чистого клонирования, публичность репозитория, зелёный Actions и наличие artifact. Защита проекта предполагает, что вы можете объяснить маршруты, формулу прибыли, тесты и CI.
